Phase Report — Application Shell & Design System Foundation

Summary
-------
Built the reusable application shell every future screen will sit inside: a responsive top nav / mobile drawer, a footer, a page container, five wrap-Vuetify design-system primitives (OHButton, OHCard, OHSection, OHPageHeader, OHLogo), a central branding config, and constants for routes/navigation/social links so nothing is hardcoded in components. No auth, actions, maps, QR, or backend work was touched, per the feature's constraints. Verified live in the browser (desktop, tablet, and a simulated mobile breakpoint), not just via build/lint.

Decisions Made
--------------
- Deleted AppLayout.vue instead of keeping it as a placeholder — it was identical to DefaultLayout.vue with zero unique behavior (no auth-differentiated shell exists yet), so keeping it would just be duplicated layout logic the feature explicitly asked to clean up.
- PageContainer is applied once, inside DefaultLayout, rather than in every view — so page width/padding consistency is automatic and views can't forget to add it.
- Rewired Vuetify's display.thresholds (mobileBreakpoint: 'sm', sm: 768, md: 1280) instead of leaving Vuetify's stock 960/1264 breakpoints — this makes useDisplay().mobile flip exactly at the project's documented tablet boundary (768px), so the top-bar/drawer switch matches the spec instead of an arbitrary Vuetify default.
- Social link buttons render disabled (not href="#") since there are no real profile URLs yet — an inert placeholder is more honest and accessible than a dead link that silently does nothing on click.
- OHButton/OHCard are intentionally trivial v-bind="$attrs" + slot passthroughs — the feature asked for a foundation, not a redesign of Vuetify's API surface.
