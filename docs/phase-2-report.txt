Decisions Made
--------------
- Used a Pinia setup store (function-style defineStore) for notifications.store.js to match the Composition API convention used everywhere else, rather than the options-style store.
- NotificationsHost shows only the most recent notification (one snackbar at a time) rather than stacking multiple — Vuetify's VSnackbar doesn't auto-stack multiple instances, and a queue-of-one is simplest for now.
- http.js is created but not imported anywhere yet, per claude.md's instruction not to call a real backend during this phase.
- No feature-specific mock services (e.g. actions.mock.js) were created — those belong to their respective feature phases (Auth in Phase 3, Actions in Phase 4), not this infrastructure phase.
